# 작성 가이드 (자동 발행 루틴용)

## 발행 스케줄 (KST 07:30)
- 화~토: `type: daily` 모닝 브리프. 미국 = 간밤 마감, 국내 = 전일 마감(07:30엔 장 시작 전).
- 월: `type: weekly` 주간 프리뷰. 지난주 정리(스냅샷 history로 5거래일 등락 계산) + 이번 주 일정(국내·미국 지표, 실적, 공모주, 만기일).
- 일: 발행 없음.
- 미국/국내 휴장일이면 그 사실을 본문에 쓰고, 해당 시장 섹션은 짧게.

## 파일
- `content/posts/YYYY-MM-DD.md` (KST 날짜). 스냅샷 `data/snapshots/YYYY-MM-DD.json`은 같은 날짜로 자동 연결.
- frontmatter:
```
---
title: "핵심 숫자 + 원인을 담은 제목 (40자 이내)"
date: YYYY-MM-DD
type: daily | weekly
summary: "2문장 요약 (150자 이내)"
tags: [미국증시, 국내증시, ...이슈 태그 2~4개]
highlights:
  - 3~4개, 각 1줄, 숫자 포함
---
```

## 본문 구조 (daily)
1. `## 간밤 미국: ...` 3대 지수 + 상승/하락의 핵심 원인 1~3개
2. `## (그날의 테마)` 섹터·종목 온도차. 필요하면 표(구분/종목/등락/해석)
3. `## 국내 증시: ...` 전일 마감, 수급(외국인/기관/개인), 주도·소외 업종, 오늘 장 전망 포인트
4. `## 환율·금리·원자재` 원/달러, 미 10년물, 유가, 금 (+비트코인은 특이할 때만)
5. `## 오늘·이번 주 체크포인트` 시간(KST) 포함 일정 3~5개
6. `## 한 줄 정리` 인용구 1개
7. `### 참고 기사` 실제로 읽은 기사 링크 4~8개 (검색 결과의 URL 그대로)

## 원칙
- 숫자는 스냅샷 JSON이 1차 출처. 기사 숫자와 다르면 스냅샷 기준으로 쓰되, 기사에만 있는 숫자(개별 종목 등락 등)는 기사 그대로 인용.
- 원인/해석은 반드시 검색한 기사에 근거. 근거 없는 추측 금지, 전망은 "~할 가능성", "~에 주목" 수준으로.
- 특정 종목 매수/매도 권유 금지. 목표가 언급 시 "OO증권은 ~ 제시" 형태로 출처 명시.
- 기사 문장을 그대로 복사하지 말고 요약·재서술.
- 해요체, 짧은 문장, 핵심 숫자는 **굵게**. 이모지 금지. 분량 1,500~3,000자.
- 색상 규칙(상승 빨강/하락 파랑)과 면책 문구는 템플릿이 자동 처리.
